## Links: a redirect the script gets before the copy exists

Status: design (2026-10-09), not built.

### Why

`wb.cloudcopy()` makes a Google Sheet copy with the user's key. Measured with the offer template
(2026-10-09): `files.copy` takes 3.8–5.4 s, and Google refuses pre-generated ids for Sheets
(`403 generatedIdNotSupported`), so the copy's own URL cannot be known before it exists. Renaming
a ready-made spare copy takes 1–2 s and needs spares lying around in Drive.

So the script gets an **Archiyou link** instead: it exists at once, says *"almost ready"* until the
copy is made, and redirects to it afterwards. Everything slow happens in the background.

### The URL

```
https://archiyou.com/go/7Kp3xQm9Zb
```

- **Short, readable prefix**: `/go/` says what it does (a redirect), and stays out of the way of the
  app's own routes (`/configurators/`, `/api/`, the editor).
- **On the app's own domain**: people trust a link to archiyou.com, and Caddy already routes a
  path prefix to the API (`/configurators/*`); `/go/*` is the same two lines.
- **An opaque, random key, not a name or a counter**: 10 characters of base58 (no `0 O I l`, so it
  survives being read aloud or retyped), from `crypto.randomBytes` — about 58 bits. Not guessable,
  so links cannot be enumerated; the rate limit on `/go/` covers the rest.
- **No title in the URL**: titles change, contain anything, and would leak in shared links. The
  page and the Drive file carry the title.

### How it behaves

| State | `GET /go/:key` |
|---|---|
| `pending` | `200` HTML: *"This link is almost ready — the spreadsheet is being made."* Refreshes itself every 3 s (`<meta http-equiv="refresh">`, no script needed). |
| `ready` | `302` to the target. Not `301`: browsers cache a 301 forever, and a target may be set or changed later. |
| `failed` | `404` HTML with the reason the editor gave (*"the copy could not be made"*). |
| `pending` for over 15 min | the same as `failed`: the editor that was making it is gone. |
| unknown key | `404`. |

Every response: `Cache-Control: no-store`, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`.

**Not an open redirect.** A target must be `https://docs.google.com/…` or `https://drive.google.com/…`
(a list in the server config, so later kinds can add theirs). Anything else is refused when it is
set, so an Archiyou link can never send someone to a phishing page.

### API

| Route | Who | |
|---|---|---|
| `POST /links` `{ kind: 'google-sheet-copy', title? }` → `201 { key, url }` | signed in, rate limited | Reserve a link, `pending`. |
| `PUT /links/:key` `{ target }` or `{ error }` → `204` | the owner | Mark it `ready` with its target, or `failed` with a message. |
| `GET /go/:key` | anyone | The redirect, or the page above. |

### Table

```
links
  key         text primary key          -- the 10-char id
  owner       text not null             -- users.id
  kind        text not null             -- 'google-sheet-copy'
  title       text                      -- for the waiting page
  target      text                      -- set when ready
  status      text not null             -- 'pending' | 'ready' | 'failed'
  message     text                      -- why it failed
  created     timestamptz not null default now()
  updated     timestamptz not null default now()
  index links_by_owner (owner)
```

One Drizzle migration. The local `.env` points at the production database, and `migrateOnBoot()`
deliberately does not migrate a shared database: the migration is applied on purpose
(`pnpm db:migrate`), after a confirmation.

### The copy, with a link

In the editor (`cloud-copies.ts`), when a copy is to be made:

1. `POST /links` (about 0.1 s) → the link. The run's answer is `{ status: 'copied', url: <link> }`:
   the script runs again at once and has a URL to show or mail.
2. In the background: `files.copy` with `appProperties.archiyouLink = <key>` (4–5 s) →
   `PUT /links/:key { target }` → write the values → share, if asked.
3. Anything failing → `PUT /links/:key { error }`, and the next run says so (as now).

Earlier copies found in Drive carry their `archiyouLink`, so `'existing'` and `'blocked'` answers
return the same link. A copy made before links existed returns its Drive URL.

**Signed out** (an unsaved draft without an account): no link can be reserved, so the editor waits
for `files.copy` as it does now and returns the Drive URL.

What the script sees stays `{ url, title, status, messages }` — `url` is the link. Total wait for
the offer script: two runs (~0.4 s each) and one `POST` (~0.1 s), instead of ~4.4 s.

### Later

- **No wait at all**: the editor keeps a few reserved keys per session, so the answer needs no
  request. Only worth it if `POST /links` shows up in the timings.
- **Configurators**: when copies are made server-side with a released key (PROTECTED_CONTENT §8),
  the same links work for visitors — the visitor gets the link at once, the server fills it in.
- **Other kinds**: an exported file (`wb.xlsx()` stored server-side), a generated PDF — anything
  slow to make that someone wants a URL for now.
- **Owner housekeeping**: list and delete one's links (a Keys-like menu). Not needed to start.

### Work

- Server: `links` table + migration; `routes/links.ts` (the three routes, the waiting page, target
  allowlist, rate limits); tests.
- Caddy: `handle /go/* { reverse_proxy api:4100 }` in each site block.
- Editor: `cloud-copies.ts` reserves the link and finishes in the background; `secret-manager.ts`
  tags the copy with `archiyouLink` and reads it back from earlier copies; tests.
- cloudcalc DOCS: the url is a link that works when the copy is ready.
