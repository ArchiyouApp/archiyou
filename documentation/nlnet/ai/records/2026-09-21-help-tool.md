## Archiyou Help — research, design and staged plan

### Context

Archiyou has no onboarding, tutorials or in-app reference. New users land in a code editor with a
dimmed, dead `?` button (`packages/ui/src/editor/main-menu.ts:75`, "Not built yet"). We want one
**help tool** in the right toolbar with modes *Onboarding*, *Tutorials*, *API reference* (AI chat
later), driven by **markdown in the open-source repo** so content is easy to iterate on,
contribute to, translate with AI, and later publish on docs.archiyou.com without rewriting.

#### Decisions taken (with the user, 2026-09-21)

| Question | Decision |
| --- | --- |
| Standalone docs site | **Deferred.** Build the in-editor tool now; keep the format generator-neutral (Starlight recommended later, see "Research") |
| Tutorial layout | **One `.md` per tutorial, `## ` = step**, code-fence meta words drive the editor |
| Delivery | **Bundled with the editor** (Vite lazy raw imports), no runtime fetch |
| Languages, first wave | en source + nl, de, fr, es, pt, it, pl, tr, **ja, zh-CN, ko, ar** (CJK + RTL from day one) |

#### What exploration found (shapes everything below)

- **Editor is Lit 3 + Web Awesome + CodeMirror 6 + `@lit-labs/signals`** — no Vue. Components live in
  `packages/ui`, state in `apps/editor/src/state/*`.
- **A generic tool abstraction exists**: `ToolDef` (`packages/ui/src/editor/toolbar.ts:9`), registered in
  one literal array `TOOLS` (`apps/editor/src/pages/editor.ts:53`). Tools get no props; they read signals.
- **Markdown is solved**: `renderMarkdown()` in `packages/ui/src/utils/markdown.ts` (markdown-it +
  DOMPurify, `html:false`). House style for a markdown browser: `packages/ui/src/editor/modules-menu.ts`.
- **Context-lookup machinery exists**: `buildScopeTypeMap`, `extractChainRoot`, `resolveType`,
  `FACTORY_RETURN_TYPES` in `packages/ui/src/editor/completions.ts:68-165`.
- **Hard parts**: (a) every tour target sits 4-6 shadow roots deep and almost nothing has a stable hook
  (`id="tool-btn-${i}"` is positional); (b) TSDoc is thin (`Modeler.ts`: 0 `@param`, 2 `@example`;
  `Fab.ts`: none) and the `$` globals are defined inline in `Runner.ts:484-546`, so typedoc has no symbol
  for `$component`; (c) `@lit/localize` is half-wired (only `nl`, generated locale modules missing) and
  the editor has no locale switcher.

### Research summary

**Docs generators** (for later). VitePress 1.6.4: lightest, but no i18n fallback (missing page = 404),
MiniSearch indexes nothing for CJK, 2.0 alpha for a year, and its Vue advantage is worthless here.
**Astro Starlight 0.42: recommended when the site is built** — untranslated pages fall back to English
with a notice, RTL, Pagefind per-language index incl. CJK, web components render natively,
`starlight-typedoc` for the reference. Rejected: Docusaurus (React, heavy), Fumadocs (Next), Nuxt
Content/Docus (whole Nuxt runtime), MkDocs Material (maintenance mode since Nov 2025), Mintlify (paid).

**Exemplars and what we copy**
| Product | Copy |
| --- | --- |
| Strudel REPL | one JSON generated from source comments feeds docs *and* in-app reference; **every example is executed in CI** |
| Godot editor | F1 = search help, Shift+F1 = help for symbol at cursor; reference is shipped data, not a link |
| Vue / Svelte tutorials | plain markdown steps + code injected into a live editor; "reset/show me" affordances |
| Processing "Find in Reference" | dumb token lookup is enough; ambiguity → show all owners |
| model-viewer docs | poster → click-to-activate for heavy viewers (docs site, later) |

**Tutorial encoding.** Conventions that survive GitHub, any static generator and an LLM translator:
flat frontmatter, **code-fence meta words**, **HTML comments**. Avoid MDX/Markdoc/`:::` directives
(render as junk on GitHub, translators mangle them, the in-app panel would need extra parsers).
No established prior art for DOM targets in markdown — we define our own comment directive.

**Tour libraries.** Shepherd (since v14) and Intro.js are AGPL — out. driver.js 1.8 (MIT, ~5 kB gz) is
the good one, but our tour text lives *in the help panel*, so we only need a spotlight, not popovers:
**~80 LOC of our own** (fixed div + `box-shadow: 0 0 0 9999px`, tracked with ResizeObserver) and no
dependency. driver.js stays the fallback if that proves fiddly.

**Context lookup.** Token + receiver heuristic (what Godot/Processing do) covers fluent CAD scripts;
a TypeScript language service in the browser (~1.5 MB gz) is not justified.

**AI translation.** Lingo.dev / "Markdown Translator" action validate the design: per-file source
hash stored *in the translated file*, mask code before sending, whitelist frontmatter keys, glossary,
structural validation, never overwrite human edits. ~180 LOC script, no SaaS.

### Content format (the contract)

```
help/                          ← repo root; not "docs" (collides with the docs script module)
  glossary.json                ← do-not-translate list + per-locale term map
  en/
    onboarding.md              ← same format as a tutorial
    tutorials/simple-table.md, cabinet.md, csg.md, sketching.md, assets.md,
              components.md, docs.md, calc.md
  nl/ de/ … ar/                ← machine-translated mirrors (same paths)
```

```markdown
---
title: A simple table
description: Boxes, moves and parameters
level: beginner
order: 1
---

## Let's start with a box            ← every "## " starts a step
The table top is just a box.

```js run                            ← run    = replace the script with this, execute
top = box(1200, 700, 30)
```

## Add a leg
<!-- highlight: viewer -->           ← spotlight a registered UI target during this step
```js append                         ← append = add to the tutorial's code so far, execute
leg = box(60, 60, 720)
```                                  ← a fence without meta is display-only
```

- Frontmatter is **flat `key: value` only** → parsed in ~10 LOC, no YAML dependency.
- The player computes the code for step N by folding fences 1..N, so Back/jump always works.
- The tutorial chooser list is generated from the frontmatter of `tutorials/*.md` (sorted by `level`, `order`).
- `highlight` ids come from a frozen `HELP_TARGETS` list; a test fails on unknown ids.
- Docs-site later: `run`/`append` fences become poster + "Open in editor" (`/editor?tutorial=slug`);
  comments are invisible; nothing in the file is editor-specific syntax. `help/<locale>/` maps 1:1
  onto Starlight locale directories.

### The help tool

```
┌ Help ───────────────────────── [EN ▾] [×] ┐     Right toolbar: last button, pushed to the
│  Start │ Tutorials │ Reference │ (AI)      │     bottom (ToolDef gets optional align:'end').
├────────────────────────────────────────────┤     exclusive:false, width 32 → usable next to
│ TUTORIAL  A simple table        step 2 / 7 │     the console.
│ ## Add a leg                               │
│ prose…                                     │     Start      = onboarding.md in the same player,
│ ┌ js ───────────────────────┐              │                  with spotlight on highlight targets
│ │ leg = box(60, 60, 720)    │ [Apply+Run]  │     Tutorials  = chooser cards → player
│ └───────────────────────────┘              │     Reference  = search box + entry view +
│ [Back]  ● ● ○ ○ ○ ○ ○   [Next]   Restart   │                  "follow cursor" toggle
└────────────────────────────────────────────┘
```

**Onboarding**: first editor visit (no `localStorage['archiyou:help:onboarded']`) opens the tool in
Start mode. Steps highlight main menu, file menu, code box, Run (Ctrl+Enter), params, viewer, toolbar,
and end by offering the first tutorial. Skip/finish sets the flag; re-runnable from the Start tab.

**Tutorials**: starting one calls `createNewScript()` (user work is never overwritten). Next applies
the step code via `updateScriptCode()` and executes. Deep link `/editor?tutorial=<slug>` copies the
`_consumeNewQueryParam()` pattern (`editor.ts:368`).

**Reference — the hierarchy**
- Level 0 *Globals*: factory functions (`box`, `sketch`…), `$` functions (`$component`, `$pipeline`,
  `$module`, `$handle`, `$import`, `$PARAMS`), module objects (`docs`, `calc`, `make`, `fab`, `materials`…).
- Level 1 *Classes* (`Mesh`, `Curve`, `ShapeCollection`, `Document`, …) → members. Entry id = `Owner.member`.
- Entry: `{ id, name, owner?, kind, sig, returns?, summary, params[], examples[] }`; examples get the same
  Apply+Run button as tutorials.
- **Lookup at cursor** (F1, or live when "follow cursor" is on): word at cursor →
  1. not preceded by `.` → prefix match in Globals (`$comp` → `$component(`); a user `$WIDTH` → card
     explaining script params, linking `$PARAMS.define`;
  2. preceded by `.` → resolve receiver with the existing `extractChainRoot`/`resolveType`/scope map,
     then walk the chain through each entry's `returns` (`$component('x').params(` → `ComponentImporter.params`);
  3. receiver unknown → list every owner that has that member, common classes first.
- Search: scored prefix/substring over ~1200 entries in ~25 LOC — no search library.
