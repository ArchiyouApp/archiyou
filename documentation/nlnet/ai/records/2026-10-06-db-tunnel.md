## Work (agent output; no separate plan)

### `pnpm db:tunnel`

`pnpm db tunnel` (scripts/db-remote.mjs) already existed, so no new script: `db:tunnel` is
an alias for it with `--port 15432`, because the local dev Postgres container already
holds localhost:5432.

### scripts/db-remote.mjs

- `let master` moved above `fail()`. Any early failure (here: no terminal to prompt on)
  called `closeMaster()` while `master` was still in its temporal dead zone, and the
  user saw a ReferenceError instead of the message.
- The tunnel's ssh runs with `ExitOnForwardFailure=yes`. Without it a busy local port is
  only a warning, ssh stays connected, and the dev server talks to the LOCAL database
  while the tunnel looks open.
- The tunnel prints the `.env` line and the command to run on separate lines. The old
  `SERVER_DATABASE_URL=… pnpm dev:server` line, pasted into .env whole, made the
  database name `archiyou pnpm dev:server`.

### apps/server/src/db/migrate.ts

`migrationState()` caught every error as "no migrations applied", so a wrong database
name, a wrong password or an unreachable host was reported as "database is BEHIND, run
`pnpm db:migrate`". Only undefined_table and invalid_schema_name (42P01, 3F000; the code
sits on Drizzle's DrizzleQueryError or its cause) still count as 0 applied; anything else
stops the boot with `Cannot read the migration state of <database>: <reason>`.

### Checked

Server typecheck; `node --check` on the script; migrateOnBoot against the LOCAL dev
container: a missing database and a wrong password give the driver's message, a fresh
empty database still gives "BEHIND, 1 vs 0", the dev database boots. Read-only through
the tunnel: production has its one migration applied.
